# Расписание

Прототип составления недельного расписания: секции слева, сетка Пн–Пт справа. Есть перенос мышью, клавиатурное управление, редактор занятий, фильтры и Undo/Redo. Допустимость размещения рассчитывается для подсветки слотов и проверяется перед изменением расписания.

## Запуск

```bash
pnpm install
pnpm dev
```

В проекте закреплена версия pnpm в `package.json`.

- `pnpm test` — запуск существующих тестов Vitest.
- `pnpm build` — проверка TypeScript и production-сборка Vite.
- Для демонстрации ошибки загрузки откройте `/?fail=1`, затем нажмите «Повторить».

## Структура

Все пути ниже относятся к `src/`.

- `schedule/` — правила предметной области: конфликты, подбор аудитории, назначение преподавателя, прогресс и выбор секций. Чистый TypeScript.
- `interaction/` — карта клавиш, правила переноса, навигации, групп и возврата в список карточек. Без React, DOM и Zustand. Приоритеты описаны в `interaction/README.md`.
- `app/schedule.store.ts` — изменение занятий и история их снимков; также хранит назначения преподавателей.
- `app/providers.tsx` — состояние взаимодействия и применение решений; `app/use-dnd-handlers.ts` — обработчики Drag & Drop.
- `features/` — хуки, подготовка данных для интерфейса и вызовы операций стора.
- `accessible/` — адаптеры клавиатурной навигации и DOM-фокуса.
- `ui/` — компоненты и обработчики интерфейса. Разделение логики ещё не завершено: часть последовательностей событий остаётся здесь и в хуках.
- `data/` — исходные данные, разбор данных и localStorage.

## Возможности

- Undo/Redo для изменений занятий.
- Поиск секций по названию и коду, фильтры по преподавателю и аудитории.
- Группировка списка по дисциплинам или преподавателям.
- Подсветка доступных и недоступных слотов при переносе.
- Автоматический подбор свободной аудитории с подходящей вместимостью; предпочтительный тип аудитории — мягкое условие.
- Копирование занятия и режим повторного размещения.
- Изменение порядка карточек внутри одной клетки.
- Имитация загрузки API с состояниями загрузки, ошибки и повторной попыткой.
- Сохранение занятий и их истории в localStorage.

## Клавиатура

- Стрелки — навигация.
- Пробел — взять или поставить карточку.
- Enter — редактировать.
- Shift — режим копирования/повторного размещения.
- Tab при работе с карточкой — переключение списка и сетки.
- Delete / Backspace — удалить занятие.
- Escape — отменить действие или закрыть текущий редактор.
- Command+Z на macOS / Ctrl+Z на Windows — отмена; с Shift — повтор. На Windows также Ctrl+Y.

Общая карта клавиш и подсказки находятся в `interaction/keyboard.ts`. Возврат после отмены зависит от источника карточки и выполненных действий; правила описаны в `interaction/README.md`.

## Правила расписания

- Секция — отдельная группа дисциплины со своим идентификатором. Преподаватель назначается секции и применяется ко всем её занятиям.
- Можно сохранить секцию без преподавателя; интерфейс показывает «Нужен преподаватель».
- Один преподаватель может вести разные дисциплины, но не две секции одной дисциплины.
- В один день и один временной слот нельзя назначить два занятия одной секции, одного преподавателя или в одной аудитории. Учитывается недоступность преподавателя и вместимость аудитории. Проверка использует идентификаторы слотов, а не произвольные интервалы времени.
- В клетке может быть несколько занятий, если эти ограничения соблюдены.
- Занятия сверх недельной нормы разрешены и отмечаются как дополнительные. Это превышение нормы секции, а не персонального лимита нагрузки преподавателя.

## Ограничения

- Виртуализация не реализована: `schedule/virtual-window.ts` только выводит сообщение. Порога автоматического включения нет.
- Интерфейс рассчитан на десктоп; полноценная мобильная адаптация не реализована.
- Клавиатурное управление есть, но поддержка screen reader отдельно не подтверждена.
- История и localStorage сохраняют занятия, но не отдельный словарь назначений преподавателей для секций без занятий.
- При первом чтении сохранения без маркера миграции `ala-too-section-teacher-v2` календарь и история сбрасываются.
- Сервер, авторизация и база данных отсутствуют.
- Полный перенос решений из обработчиков в независимые модули ещё не завершён.
