# Расписание

Прототип составления недельного расписания: секции слева, сетка Пн–Пт справа. Есть перенос мышью, клавиатурное управление, редактор занятий, фильтры и Undo/Redo. Допустимость размещения рассчитывается для подсветки слотов и проверяется перед изменением расписания.

## Стек

React 19, TypeScript, Vite, Zustand и dnd-kit. React Compiler подключён в `vite.config.ts` через `reactCompilerPreset` и `@rolldown/plugin-babel`. Компоненты пишутся как обычные чистые функции; ручная мемоизация добавляется только при конкретной необходимости.

Стили — CSS Modules и общие токены в `src/app/tokens.css`. Проверки: TypeScript, Oxlint с правилами `@oxyhub/oxlint-plugin` и Vitest.

## Запуск

```bash
pnpm install
pnpm dev
```

В `package.json` закреплён `pnpm@12.10.1`. Все команды запускаются из корня проекта.

- `pnpm lint` — проверка кода.
- `pnpm lint:fix` — проверка с автоматическими исправлениями; изменения после запуска нужно просмотреть.
- `pnpm preview` — просмотр готовой сборки после `pnpm build`.
- `pnpm test` — запуск существующих тестов Vitest.
- `pnpm build` — проверка TypeScript и production-сборка Vite.
- Для демонстрации ошибки загрузки откройте `/?fail=1`, затем нажмите «Повторить».

## Структура

Все пути ниже относятся к `src/`.

- `schedule/` — правила предметной области: конфликты, подбор аудитории, назначение преподавателя, прогресс и выбор секций. Чистый TypeScript.
- `interaction/` — правила переноса, разрешения навигации, групп и возврата в список карточек. Без React, DOM и Zustand. Приоритеты описаны в `interaction/README.md`.
- `app/schedule.store.ts` — изменение занятий и история их снимков; также хранит назначения преподавателей.
- `app/providers.tsx` — состояние взаимодействия и применение решений; `app/use-dnd-handlers.ts` — обработчики Drag & Drop.
- `features/` — хуки, подготовка данных для интерфейса и вызовы операций стора.
- `accessible/` — клавиатурные команды и подсказки, навигация, фокус диалогов, способ ввода и объявления для скринридеров.
- `ui/` — компоненты, представления и обработчики интерфейса. Связанные файлы используют имя области и роль через точку: `lessonCard.body.tsx`, `lessonEditor.keyboard.ts`, `slotLessons.reorder.ts`.
- `data/` — исходные данные, разбор данных и localStorage.

## Возможности

- Undo/Redo для изменений занятий.
- Поиск секций по названию и коду, фильтры по преподавателю и аудитории.
- Группировка списка по дисциплинам или преподавателям.
- Подсветка доступных и недоступных слотов при переносе.
- Автоматический подбор свободной аудитории с подходящей вместимостью; предпочтительный тип аудитории — мягкое условие.
- Копирование занятия и режим повторного размещения.
- Изменение порядка карточек внутри одной клетки.
- Имитация загрузки API с состояниями загрузки, ошибки и повторной попыткой.
- Сохранение занятий и их истории в localStorage.

## Управление мышью

- Перетащите секцию из списка в ячейку, чтобы назначить занятие. Можно также взять карточку кликом и поставить следующим кликом.
- Перенос занятия между ячейками проходит через проверку конфликтов. Подсветка показывает допустимые места и причины отказа.
- При переносе карандаш на исходной карточке открывает редактор. У секции он открывает назначение преподавателя, у занятия — преподавателя и аудиторию.
- Для двух занятий в одной ячейке доступна перестановка: положение указателя в верхней или нижней половине выбирает порядок, подсказка показывает «Поставить первым/вторым». Клик подтверждает перенос взятой кликом карточки, отпускание мыши завершает Drag & Drop.
- При трёх и более занятиях ячейка показывает компактные строки. Нажатие открывает список занятий.
- В настройках можно включить клавиатурные подсказки и демонстрационный набор из 500 секций. Переключение набора сбрасывает расписание.

## Клавиатура

- Стрелки — навигация.
- Пробел — взять или поставить карточку.
- Enter — редактировать.
- Shift — режим копирования/повторного размещения.
- Tab при работе с карточкой — переключение списка и сетки.
- Delete / Backspace — удалить занятие.
- Escape — отменить действие или закрыть текущий редактор.
- Command+Z на macOS / Ctrl+Z на Windows — отмена; с Shift — повтор. На Windows также Ctrl+Y.
- Command+K на macOS / Ctrl+K на Windows — фокус на поиске секций.
- В раскрытом Select стрелки выбирают пункт, Home / End переходят к первому / последнему доступному пункту; ввод текста ищет по началу названия.

Общая карта находится в [`src/accessible/keyboard.bindings.ts`](src/accessible/keyboard.bindings.ts): `keyboard`, `commandModifier`, `keyboardHints` и функции сопоставления. Обработчики используют смысловые действия: `matchesKey('cancel', event.key)`, `matchesKey('edit', event.key)`, `matchesKey('place', event.key)`. Названия физических клавиш и платформенных модификаторов задаются в этой карте. Возврат после отмены зависит от источника карточки и выполненных действий; правила описаны в `interaction/README.md`.

## Где менять интерфейс

- `ui/section-list/section-list.tsx` собирает панель из `sectionList.header.tsx`, `sectionList.body.tsx` и `sectionList.footer.tsx`. Входы панели разделены на `hidden`, `filters`, `content` и `navigation`.
- `ui/lesson-card/lesson-card.tsx` отвечает за перенос и внешнюю оболочку; `lessonCard.body.tsx` — за содержимое, `lessonCard.actions.tsx` — за действия исходной карточки. Класс `styles.card` нужен обычной карточке и превью переноса.
- `ui/lesson-editor/lesson-editor.tsx` управляет редактором; `lessonEditor.fields.tsx`, `.options.ts`, `.draft.ts`, `.save.ts`, `.focus.ts` и `.keyboard.ts` разделяют поля, варианты выбора, подготовку значений, сохранение и управление фокусом.
- `ui/schedule-grid/slotLessons.view.ts` определяет раскладку ячейки; `.reorder.ts`, `.commands.ts` и `.picker.ts` управляют перестановкой, командами и списком занятий.
- `ui/slot-cell/slotCell.model.ts` вычисляет состояние ячейки; `.position.ts` позиционирует подсказки относительно неё.
- Общие подписи и представления: `ui/teacher-label.ts`, `ui/section-code.ts`, `ui/room-type.ts`, `ui/data-attribute.ts`.

Сложные обработчики и вычисления выносятся перед JSX или в связанный модуль. Условия получают смысловые имена; вложенные тернарники не используются. Разделение компонентов должно сохранять CSS-классы, DOM-структуру, фокус и порядок событий.

## Правила расписания

- Секция — отдельная группа дисциплины со своим идентификатором. Преподаватель назначается секции и применяется ко всем её занятиям.
- Можно сохранить секцию без преподавателя; интерфейс показывает «Нужен преподаватель».
- Один преподаватель может вести разные дисциплины, но не две секции одной дисциплины.
- В один день и один временной слот нельзя назначить два занятия одной секции, одного преподавателя или в одной аудитории. Учитывается недоступность преподавателя и вместимость аудитории. Проверка использует идентификаторы слотов, а не произвольные интервалы времени.
- В клетке может быть несколько занятий, если эти ограничения соблюдены.
- Занятия сверх недельной нормы разрешены и отмечаются как дополнительные. Это превышение нормы секции, а не персонального лимита нагрузки преподавателя.

## Ограничения

- Виртуализация списков и порог её автоматического включения не реализованы.
- Интерфейс рассчитан на десктоп; полноценная мобильная адаптация не реализована.
- Клавиатурное управление есть, но поддержка screen reader отдельно не подтверждена.
- Автоматические тесты проверяют отдельные правила расписания и взаимодействия; полного набора браузерных проверок переноса, фокуса и оформления пока нет.
- История и localStorage сохраняют занятия, но не отдельный словарь назначений преподавателей для секций без занятий.
- При первом чтении сохранения без маркера миграции `ala-too-section-teacher-v2` календарь и история сбрасываются.
- Сервер, авторизация и база данных отсутствуют.
- Полный перенос решений из обработчиков в независимые модули ещё не завершён.
